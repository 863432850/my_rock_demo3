# 碳资产对标分析报告 — 界面复刻提示词

> **数据口径（先读这条）**
>
> 1. **本企业碳资产数据只能来自入参 `carbonAsset.volume`，一律不兜底。**
>    - **入参给 `0` 或字段缺位 → 视为"无有效数据"**，全篇进入无有效数据态：摘要第 1 卡数值 `--`、排名卡 `--`、对标总览图**不画**、结构与储备提升章节改为"数据缺失"措辞。
>    - **严禁**用行业均值、相邻期插值、等比放大、联网检索来"补"一个碳资产量，也**不得**改用某个基准值代入推算。
> 2. **本报告是"实物量"口径（万tCO₂），全篇不出现金额。** 碳价逐日波动，把「碳资产总价值（万元）」当入参会让"同一天量、不同天价"的数据不可比——因此入参**不设** `carbonAsset.totalValue`，报告**也不做**"量 × 价"折算，全文不得出现「万元」「元/tCO₂」，也不得出现收益率这类必须依赖金额的指标。
> 3. **企业侧只采集"碳资产量"一项。** 年履约排放量在当前数据条件下无法获取，因此入参**不设** `annualEmission`，正文也**没有**「配额履约覆盖率」「履约缺口」「补缺口成本」这类内容。
> 4. **资产结构（配额 / CCER / 其他）由碳资产量按固定占比拆分**（见 2.5(2)(3)），这是**结构性口径**，不是三项独立台账数据；文档与页面都不得暗示它们是分别统计来的。
> 5. **对标基准（区域均值 / 行业均值 / 行业先进值 / 样本企业数 / 排名）属 L3 兜底生成**，按 2.5(3) 的公式与稳定种子确定性生成，**不是接入的真实统计**；正文不得暗示这些数字来自真实登记簿或结算平台。
> 6. **行业先进值必须高于行业均值**：碳资产量「越大越好」，先进值应更优 = **更大**，即 `advancedVolume > indAvgVolume`。这与碳排放对标报告的 `advanced = indAvg × 0.92x`（强度越低越好）**方向相反**，不要照抄。
> 7. 全篇禁止出现 `NaN`、`undefined`、`Infinity`、`∞`；也禁止出现「示例」「演示」「模拟」「占位」「待补充」等字样。
> 8. 本报告只做**企业层级**碳资产对标（规模 / 结构 / 储备），**不含**碳交易流水明细、履约台账明细或 CCER 项目清单。
>
> 本文档描述「碳资产对标分析报告」（在碳对标分析页点击「碳资产对标」页签 →「开始对标」后进入的全屏 A4 报告页）的完整界面规格。按「一、入参」给定 JSON 输入，严格按「二、任务」的规格生成与原型一模一样的界面。  
> 本文档是自包含的：不需要访问任何原项目源码。  
> 使用方法：把入参 JSON 改成目标值，连同本文档全文发给 AI 即可。

## 二、任务

### 数据来源与真实性要求（先读）

本报告的数字分属三层，**不要笼统写成"数据来自登记簿/结算平台"**：

**A. L1 入参直取（零兜底）——本企业碳资产量**

- `carbonAsset.volume` → 摘要第 1 卡、各处对比小字、排名与超越比例、规模对标表「企业数据」格、对标总览图「本企业」条、第五章两档差距量。
- **入参给 `0` 或缺失就写 `--`**，不推算、不检索替换、不用行业经验值补位。详见 2.5(3)(4)(6)。
- **单位一律是「万tCO₂」**，不要写成金额、也不要乘以任何碳价。

**B. 结构性派生——资产结构（配额 / CCER / 其他）**

- 三项持有量由 `carbonAsset.volume` **按固定占比**拆分（`0.88 / 0.07 / 余额`），单位同为万tCO₂。
- 这**不是三项独立台账数据**：正文不得写"配额持有 X 万t、CCER 储备 Y 万t"却不交代拆分口径；份额必须在文档中显式给出（2.5(2)）。
- 拆出的三项**必须满足**：三项之和 = `entVolume`（用减法保证，不要各自四舍五入后相加）。

**C. L3 兜底生成——各级对标基准**

- 区域均值 / 行业均值 / 行业先进值 / 样本企业数 / 排名，按 2.5(3) 的公式与种子 `SEED = strHash(region) ^ (year × 131) ^ (month × 977)` **确定性生成**，同入参同结果。
- 这些基准是**演示口径的兜底值**；**不得**在页面上声称它们来自「区域碳市场登记簿」「碳交易结算平台」等具体来源（原文案仅作为排名口径说明保留，不得扩写）。
- 基准必须满足相对关系：`advancedVolume > indAvgVolume`；`region = 全国` 时 `regionAvgVolume = entVolume`。
- ⚠️ **注意方向**：碳资产量越高越好，先进值是**上界**（比行业均值大 12%~16%）。**不要**照搬碳排放对标报告的「先进值 = 均值 × 0.92x」。

**D. 通用禁令**

- 不得出现与入参量级明显不符的常量（如碳资产 320 万tCO₂ 的企业，报告里不得出现「碳资产 6,000 万tCO₂」这类越界数字）。
- 不得把某一家企业的公开数字直接套给入参企业。
- 不得写「数据待补充」「暂无数据」「（示例）」；一律按 2.5(6) 与附录 C 规定的措辞处理。

**(5) 一、报告定位与核心思路**（三段，成文模板）

- 段 1：「本报告为 {companyName} 专属碳资产对标专项报告，聚焦企业碳资产的**规模与结构**开展量化研判，与碳排放对标（强度/降碳空间）形成互补——碳排放对标看「排了多少、强度如何」，本看「手里有多少碳资产、储备结构是否合理」。报告以「{region}」为对标区域、以「{year}年{month}月」为对标期间，将本企业碳资产量与区域平均值、行业平均值、行业先进值进行四维对比，并拆解配额、CCER 与其他碳资产的配置结构。」
- 段 2：「报告核心思路：**一排名、二对比、三结构、四建议**——先以碳资产规模排名锚定企业在区域同行业中的位置；再与区域、行业、先进三级基准逐层对比；拆解配额、CCER、其他碳资产的配置结构并定位储备短板；最终给出碳资产储备与结构优化建议，为企业盘活碳资产、提升储备厚度提供决策依据。」
- 段 3：「数据口径说明：碳资产量为**实物量口径**（万tCO₂），由配额持有量、CCER 储备量与其他碳资产三部分构成；碳价逐日波动，故本报告不做「量 × 价」折算、全篇不出现金额，以保证不同期间、不同企业之间可比。区域与行业数据来源于区域碳排放权登记簿、碳交易结算平台及行业协会统计，样本企业 {entCount} 家；先进值取行业前 10% 企业水平。」

2. **（一）资产规模与对标分析**：一段成文，模板：  
   「本企业碳资产量 {entVolume} 万tCO₂，高于/低于{region}平均值 {regionAvgVolume} 万tCO₂（高出/低于区域 {abs(vsRegion)}%），高于/低于行业平均值 {indAvgVolume} 万tCO₂（高出/低于行业 {abs(vsIndustry)}%），[已达到行业先进值 {advancedVolume} 万tCO₂ 水平 / 与行业先进值 {advancedVolume} 万tCO₂ 相比仍有 {abs(vsAdvanced)}% 差距]。在{region} {entCount} 家同行业样本企业中位列第 **{rank}** 名，超越区域内 {outperform}% 的企业，{梯队判定语}」

   无有效数据时改为：「本期未提供本企业碳资产数据，无法开展对标分析。表中各级基准值由本企业碳资产规模推导，本企业数据缺失时一并不可用；数据补齐后即可完成规模对比与排名。」
3. **（二）资产结构与配置**：一段成文 + 结构图。文案模板：  
   「本企业碳资产量 {entVolume} 万tCO₂，按用途拆分为配额、CCER 与其他碳资产三部分：配额持有量 {entAllowance} 万tCO₂（占比 {p1}%）、CCER 储备量 {entCCER} 万tCO₂（占比 {p2}%）、其他碳资产 {entOther} 万tCO₂（占比 {p3}%）。结构上以配额为绝对主体（占比 {p1}%），履约保障基础扎实；CCER 与其他碳资产合计占比 {pRest}%，可作为低成本抵销资源与流动性补充，整体配置符合「以配额保履约、以 CCER 降成本」的通用思路。」  
   其中占比 p = 该项持有量 ÷ entVolume × 100（保留 1 位小数、**不是占比链**）。**不要出现履约覆盖率、履约缺口、金额**。  
   其后接**碳资产结构分布图**（3 行横向条形，规格见 2.6），图题「（图）本企业碳资产结构分布（{year}年{month}月）」。  
   无有效数据时改为：「本期未提供本企业碳资产数据，暂不作结构分析。」（此时**不画**结构图）

**(9) 五、碳资产储备提升空间分析**

   - 无有效数据时：两段都改为「本期未提供本企业碳资产数据，无法测算储备提升空间。建议先行完成配额发放量、CCER 登记量与持有量的核算与台账核对，建立碳资产量基线……」+「建议按「保障优先、储备并重」原则推进碳资产管理工作：先把持有量基线建准、把台账建全……」。

### 2.5 数据规则（唯一数据源）

全部数值由以下代码推出。**不同入参 → 不同数据；同一入参 → 完全一致**。不要另编数字。

**(1) 稳定随机源**（原样实现，勿改）：

```javascript
function strHash(str) {                 // 区域名 → 稳定数值
  var h = 2166136261;
  for (var i = 0; i < str.length; i++) {
    h ^= str.charCodeAt(i);
    h = Math.imul(h, 16777619);
  }
  return h >>> 0;
}
function mulberry32(seed) {             // 可复现伪随机
  var a = seed >>> 0;
  return function () {
    a |= 0; a = (a + 0x6D2B79F5) | 0;
    var t = Math.imul(a ^ (a >>> 15), 1 | a);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
```

**(2) 常量（结构占比，非企业台账数据）**：

```
SHARE_ALLOWANCE = 0.88     // 配额持有量占比
SHARE_CCER      = 0.07     // CCER 储备量占比
// 其余约 0.05 归入「其他碳资产」，用减法保证三项之和 = 碳资产量
```

> **本报告没有"碳价"常量**：全篇为实物量口径（万tCO₂），不做「量 × 价」折算。若旧版文档里出现  
> `CARBON_PRICE` / `CCER_PRICE`（90 / 68 元/tCO₂），一律**删除**，不得保留、不得用于任何计算。

**(3) 计算（按以下顺序逐字实现；`rnd()` 的调用顺序直接决定兜底基准，不得增删或调换）**：

> 舍入辅助：`r0 = n => +Number(n).toFixed(0)`、`r1 = n => +Number(n).toFixed(1)`、`r2 = n => +Number(n).toFixed(2)`、`round = Math.round`。

```javascript
var IS_NATIONAL = (REGION === '全国');
var SEED = (strHash(REGION) ^ Math.imul(Y, 131) ^ Math.imul(M, 977)) >>> 0;
var rnd  = mulberry32(SEED);

// —— 1) 本企业数据（L1 入参直取，零兜底）——
var HAS_VOLUME = (carbonAsset.volume != null) && (carbonAsset.volume > 0);
var entVolume  = HAS_VOLUME ? r2(carbonAsset.volume) : null;              // 碳资产量 万tCO₂

// —— 2) 资产结构：由碳资产量按固定占比拆分（结构性口径，非三项独立台账）——
var entAllowance = HAS_VOLUME ? r2(entVolume * SHARE_ALLOWANCE) : null;               // 配额持有量 万tCO₂
var entCCER      = HAS_VOLUME ? r2(entVolume * SHARE_CCER) : null;                    // CCER 储备量 万tCO₂
var entOther     = HAS_VOLUME ? r2(entVolume - entAllowance - entCCER) : null;        // 其他碳资产 万tCO₂（减法保证三项之和 = entVolume）

// —— 3) 兜底基准（L3，全部由种子确定性生成；rnd() 无条件消耗，与入参有无值无关）——
// 注意：region='全国' 时三元短路，本行【不消耗】rnd() 调用，后续随机序列随之偏移
var regionOffset = IS_NATIONAL ? 0 : (rnd() - 0.45) * 0.12;
var uInd = rnd(), uAdv = rnd();
var regionAvgVolume = HAS_VOLUME ? r2(entVolume * (1 + regionOffset)) : null;         // 区域均值 万tCO₂
var indAvgVolume    = HAS_VOLUME ? r2(entVolume * (1 + (uInd - 0.42) * 0.10)) : null; // 行业均值 万tCO₂
// ⚠️ 先进值 = 行业均值 × (1.12 ~ 1.16)：碳资产量越大越好，先进值是【上界】
var advancedVolume  = HAS_VOLUME ? r2(indAvgVolume * (1.12 + uAdv * 0.04)) : null;    // 行业先进值 万tCO₂

// —— 4) 样本与排名（HAS_VOLUME=false 时 rank / outperform 置空）——
var entCount = IS_NATIONAL ? Math.round(1400 + rnd() * 900)
                           : Math.round(45 + rnd() * 180);

var rank = null, outperform = null;
if (HAS_VOLUME) {
  var rankPct = Math.min(0.98, Math.max(0.02,
                  0.5 - (entVolume - regionAvgVolume) / (regionAvgVolume * 0.22)));
  rank       = Math.max(1, Math.round(entCount * rankPct));
  outperform = r1((1 - rank / entCount) * 100);                           // 超越比例 %
}

// —— 5) 差距百分比（2 位小数；正值=本企业高于基准=好；HAS_VOLUME=false 时全部为 --）——
var vsRegion   = HAS_VOLUME ? r2((entVolume - regionAvgVolume) / regionAvgVolume * 100) : null;
var vsIndustry = HAS_VOLUME ? r2((entVolume - indAvgVolume)    / indAvgVolume    * 100) : null;
var vsAdvanced = HAS_VOLUME ? r2((entVolume - advancedVolume)  / advancedVolume  * 100) : null;
```

> **与旧版的差异（务必按新版实现）**：旧版入参是「碳资产总价值（万元）」并额外收 `annualEmission`，  
> 结构三项还要靠碳价（90 / 68 元/t）从金额折回持有量，另有 3 次 `rnd()` 用于编造「三类收益率」。  
> 新版改为：  
> ① 入参换成**碳资产量 `carbonAsset.volume`（万tCO₂）**，结构由总量按占比直接拆出，**不再经过碳价**；  
> ② 删掉 `entROI / regionROI / indROI` 及其 3 次 `rnd()` 消耗、删掉 `annualEmission` 与履约覆盖率链路；  
> ③ **先进值由「低于行业均值」翻转为「高于行业均值」（×1.12~1.16）**——碳资产量越大越好，旧版的 `×0.92~0.94` 是照抄排放报告的错误方向；  
> ④ 基准的 `rnd()` 改为**无条件消耗**（旧版在 `HAS_TOTAL = false` 时会少取几次，导致样本企业数偏移）。  
> 因此兜底基准的数值与旧版**不同**——这是预期的，**不要拿旧版的校验表来对**。

**(4) 第五章储备提升空间测算**（**只依赖碳资产量；`HAS_VOLUME = false` 时两档一起降级**）：

```
gapAvg      = HAS_VOLUME ? r2(max(0, indAvgVolume    − entVolume)) : --   // 差距量 万tCO₂
gapAdvanced = HAS_VOLUME ? r2(max(0, advancedVolume  − entVolume)) : --   // 差距量 万tCO₂
pctAvg      = gapAvg      == null ? -- : r2(gapAvg      / entVolume * 100) // 相对提升幅度 %
pctAdvanced = gapAdvanced == null ? -- : r2(gapAdvanced / entVolume * 100) // 相对提升幅度 %
```

> - 差距量**下限为 0**：本企业已达到该档目标时写 `0.00`（绿字），**不要写负数**。
> - `HAS_VOLUME = false` 时，「本企业碳资产量」「目标水平」「差距量」「相对提升幅度」四列写 `--`，  
>   结论两段整段改写为「本期未提供本企业碳资产数据，无法测算储备提升空间……」，  
>   **不要把 `--` 塞进原句式的数字位**，也不要用基准值代入反推一个本企业量。
> - **不涉及任何金额**：不乘碳价、不出「补缺口成本」「增量年收益」这类字段。

**(5) 数值格式**：碳资产量与各项持有量（万tCO₂）保留 2 位小数、千分位（`toLocaleString('zh-CN')`）；百分比 2 位小数（超越比例 1 位）；**全篇不出现金额单位**。

## 附录 A · 量级锚点与自检

**碳资产量（万tCO₂）的量级参照**——用于判断入参是否"一眼假"，**不是用来填数**：

| 参照       | 量级                 | 说明                                                         |
| -------- | ------------------ | ---------------------------------------------------------- |
| 配额持有量    | 与年履约排放量同量级         | 履约期内通常持有当年履约所需的大部分配额，例如年排放 320 万tCO₂ 的企业，配额持有量常在数十万至数百万吨之间 |
| CCER 储备量 | 通常为配额持有量的 5% ~ 10% | 现货抵销资源，规模随项目开发进度波动                                         |
| 其他碳资产    | 通常为配额持有量的 3% ~ 8%  | 定向储备、远期锁量等                                                 |

> 本报告的**结构占比固定为 `88% / 7% / 5%`**（见 2.5(2)），上表只用于理解量级关系，**不要**用它去反算或改写结构占比。  
> 若入参明显偏离（如企业年排放仅 320 万tCO₂ 却给碳资产量 6,000 万tCO₂），**应如实呈现并在文案中提示存疑**，**不要**替它改成"合理值"。

**本报告为何不收金额**：碳资产总价值（万元）= 持仓量 × 当期碳价，而碳价**逐日波动**（全国碳市场配额价近年大致在 60~100 元/tCO₂ 区间）。同一批持仓在不同日期折算出的金额不同，用它作入参会让不同期间、不同企业的对标结论失去可比性；同时金额口径还要求企业提供逐笔交易台账，实际很难取数。因此本版入参改为**碳资产量（万tCO₂，实物量）**，报告也**不做**任何"量 × 价"折算。

**基准的方向**：碳资产量**越大越好**，所以 `advancedVolume` 是**上界**（行业均值 × 1.12~1.16），判定「已达先进」用 `vsAdvanced ≥ 0`。这与碳排放对标报告（强度越小越好、先进值取 `indAvg × 0.92x`）**方向完全相反**，不要互相套用公式。

## 附录 B · 兜底生成规则

> **适用范围：仅用于「各级对标基准」（区域均值 / 行业均值 / 行业先进值 / 样本企业数 / 排名）。**  
> **本企业碳资产量一律不兜底**——见「数据口径」第 1 条。

**B1 基准的生成必须逐字按 2.5(3)**

- `rnd()` 的**取值顺序不可调换、不可随意增删**：`regionOffset（全国时跳过）→ uInd → uAdv → entCount`。  
  顺序一变，同一入参的基准就会变，"同条件结果一致"随之失效。
- **除 `regionOffset` 外，所有 `rnd()` 一律无条件取值**（与 `HAS_VOLUME` 无关）——旧版把取值写在  
  `HAS_TOTAL ? ... : null` 的三元里，导致「本企业数据缺失」时样本企业数会偏移，本版已修正。
- `region = 全国` 时**跳过** `regionOffset` 那一次 `rnd()` 取值——这是全国与省份序列不同的原因，务必按原文实现。
- ⚠️ **与旧版的关键差异**：本版①入参由"总价值"换成"碳资产量"、②删掉 3 次收益率 `rnd()` 与 2 次碳价折算、  
  ③先进值方向由 `×0.92~0.94` 翻转为 `×1.12~1.16`、④基准取值改为无条件消耗。因此基准数值与旧版**不同**，**不要拿旧版的校验表来对**。

**B2 基准不得反推本企业数据**

- 任何情况下都不得用 `regionAvgVolume` / `indAvgVolume` / `advancedVolume` 去"倒推"一个本企业碳资产量。  
  本企业碳资产量只有两个合法来源：**入参**，或显式&#x7684;**「无有效数据」占位 `--`**。
